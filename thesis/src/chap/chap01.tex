\chapter{绪论}
\label{chap:intro}

\section{研究背景与意义}

近年来，开源大语言模型发展迅速。以 llama.cpp \cite{gerganov2023llamacpp} 及其底层张量代数库 ggml \cite{gerganov2023ggml} 为代表的轻量级推理引擎，使得在边缘设备和普通服务器上本地部署大模型成为可能。然而，随着模型规模的不断增大，推理引擎在系统架构上日趋复杂。

大语言模型的参数规模持续增大，底层硬件的内存带宽与计算能力的矛盾日益突出。X. Ma 与 D. Patterson 指出，由大规模权重加载与自回归解码阶段引发的内存受限问题，是现代 AI 硬件面临的严峻挑战 \cite{ma2026challenges}。A. M. Jain 等人的研究表明，在高并发聊天机器人架构下，系统尾部延迟急剧上升，硬件算力接近物理极限 \cite{jain2025scaling}。为应对这一危机，底层系统软件层面开始主导架构重构。W. Kwon 等人提出了 PagedAttention 机制，将操作系统的虚拟内存分页管理思想引入 AI 领域，改变了 KV Cache 的内存分配逻辑 \cite{kwon2023efficient}。这些优化使推理引擎在系统架构上极度复杂，普遍采用多语言混合编程范式（Go、Python 与 C/C++ 混编）。

这种复杂性带来了安全隐患。2023 年，PyTorch 官方维护的 TorchServe 被发现存在远程代码执行漏洞（CVE-2023-43654） \cite{pytorchserve2024}，攻击者可通过上传恶意模型文件执行任意命令。2024 年，Ollama 框架被披露存在路径穿越漏洞（CVE-2024-37032，代号 Probllama） \cite{tzadik2024probllama}，攻击者可利用 API 数据包校验不严的问题读取服务器上的任意文件。这些漏洞的共同特点是：问题发生在高层 API 与底层文件系统之间的数据流通路径上，但现有安全工具无法有效追踪数据在这一路径上的具体流向。

具体而言，推理引擎内部的数据传输路径涉及多层语言环境：Go HTTP Handler 接收 API 请求，经由 CGO 桥接层传递给 C++ 计算层，最终触发内核系统调用。现有可观测工具在该路径上存在明显的观测盲区——API 层只能看到请求的进入和响应的输出，内核层只能看到系统调用的发生，而中间环节的函数调用关系、数据流转方向均无法被连贯还原。当安全事件发生时，分析人员难以回答"注入的数据最终触发了哪些内核操作"这一基本问题。

因此，研究如何实现开源 AI 软件内部从 API 请求到内核调用的完整调用链追踪，对提升推理引擎的可观测性和安全性具有实际意义。

\section{国内外研究现状}

在系统追踪与可观测性领域，已有多种技术可用于观测程序运行行为，但各有其适用场景与局限。

在内核动态追踪与系统可观测性领域，eBPF 经历了重要演进。自 A. Starovoitov 提交核心补丁将其重塑为通用内核虚拟机以来 \cite{corbet2014bpf}，B. Gregg \cite{gregg2020bpf} 与 D. Calavera \cite{calavera2019linux} 奠定了其在系统性能剖析领域的主导地位。随着 A. Nakryiko 引入 BPF Ring Buffer 解决并发数据无损回传 \cite{nakryiko2020ringbuf}，以及 Cilium 团队开源纯 Go 语言的 eBPF 交互库 \cite{ciliumebpf2024}，其应用边界不断拓宽。Y. Hu \cite{hu2025ebpf}、M. Ibnath \cite{ibnath2026ebeemetrics} 以及 B. Zou \cite{zou2026profinfer} 等研究者相继将 eBPF 应用于无服务器网络监控、微服务流式延迟测量以及大语言模型底层的算子级硬件剖析。在安全防护层面，ControlPlane \cite{controlplane2024ebpf}、LinuxSecurity \cite{linuxsecurity2026auditd} 与 Groundcover 团队 \cite{groundcover2024ebpf} 对 eBPF 的威胁模型及替代传统 Auditd 的微隔离实践进行了深度论述。

在跨语言程序分析方面，已有研究尝试解决多语言混合编程环境下的控制流还原问题。Go 官方团队的 CGO 工具链 \cite{goauthorscgo} 与 J. Chen 等人的实证研究 \cite{chen2026empirical} 揭示了 CGO 在类型安全上的隐患。M. Hu 等人 \cite{hu2023cross}、中科大安全实验室的 POLYCALL 项目 \cite{zheng2023effective} 以及 R. Sunil \cite{sunil2026llms} 分别尝试通过图转换算法、WebAssembly 中间表示以及大语言模型智能推断来重建多语言混合图谱。同时，在跨语言数据流分析领域，Brucker \cite{brucker2016static}、CHARON 团队 \cite{scholtes2025charon} 以及 X. Cheng 提出的 Deepwukong 图神经网络漏洞检测模型 \cite{cheng2021deepwukong}，展示了在静态环境下溯源跨界污染流的潜力。

在动态二进制插桩（DBI）体系中，D. Bruening 的 DynamoRIO \cite{bruening2003dynamorio}、C. Lattner 的 LLVM 架构 \cite{lattner2004llvm} 以及 N. Nethercote 开发的 Valgrind \cite{nethercote2007valgrind} 及其影子内存核心机制 Memcheck \cite{nethercote2007shadow}，确立了程序运行时监控的理论体系。然而，大模型推理场景在算力与内存吞吐上的极致要求，使上述重量级的分析方法面临严重的落地困境。

现有技术在追踪精度、运行时开销、业务语义理解三者之间难以兼顾，尚无成熟方案能够完整还原多语言推理引擎内部的数据传输调用链。

\section{论文主要工作}

本文针对开源 AI 推理引擎的数据传输 API 调用链分析问题，设计并实现了 HybriChain 系统，主要工作包括以下四个方面。

第一，构建了跨语言符号分类机制。针对推理引擎内部符号来源多样（Go 运行时、CGO 桥接函数、llama.cpp C++ 函数）、命名格式各异的问题，提出了八层符号分类体系，按函数职责将其划分为胶水层、API 层、批处理采样层、调度计算层、后端内存层、张量运算层、词表层和内存操作层，使跨语言调用关系具备可理解的语义层次。

第二，设计了基于 eBPF 的低开销追踪方案。采用 uprobe 在 llama.cpp 核心函数上挂载探针，采用 tracepoint 追踪系统调用，在不影响推理引擎正常运行的前提下采集调用数据。与传统 DBI 工具相比，该方案的性能开销控制在可接受范围内。

第三，提出了动静结合的调用链缝合方法。将静态符号分析得到的函数调用关系，与动态追踪采集的实际执行轨迹相结合，通过锚点匹配和时间窗口对齐，为每条跨语言调用边计算置信度标签，区分"已确认"、"已推断"和"未知"三类调用关系。

第四，构建了基于调用链的异常检测规则引擎。在缝合后的完整调用链上运行预定义规则集，实现对长阻塞同步、大块内存分配、敏感路径访问等可疑行为的自动识别与告警。

\section{论文组织与结构}

本文共分为六章。第 1 章为绪论，阐述研究背景与意义，分析国内外研究现状，并介绍本文主要工作与论文结构安排。第 2 章为相关技术综述，介绍大模型推理引擎架构、eBPF 追踪技术、跨语言程序分析方法及动态二进制插桩工具。第 3 章为 HybriChain 系统设计，详细说明各模块的设计方案。第 4 章为 HybriChain 实现方案，以 Ollama 推理引擎为靶点，说明具体实现细节与关键参数选取依据。第 5 章为实验评估，在 TinyLlama-1.1B 和 Qwen2-0.5B 模型上开展实测，评估调用链缝合准确性、性能开销及异常检测能力。第 6 章为总结与展望。
